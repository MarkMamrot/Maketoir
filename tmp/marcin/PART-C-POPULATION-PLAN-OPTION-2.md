## Part C structure

The register has six columns:

1. Item No.
2. Section / Clause
3. Date
4. Comment By
5. Clarification
6. Status (Open/Closed)

Each comment becomes one complete three-row conversation block:

1. Tenderer initial submission.
2. Fortescue response.
3. Tenderer follow-up.

Item No. and Section / Clause remain vertically merged across the three rows. Creating 92 items therefore requires 276 conversation rows, plus the register header. Clone the complete template block for every item so borders, widths, merged cells, vertical alignment and row behaviour remain intact.

## Item construction

### One comment, one item

For comment number `n`, create a distinct register item even when:

- another comment has the same anchor;
- another comment requests the same commercial outcome;
- the same redlined wording supports more than one rationale;
- the comment is an internal instruction;
- the comment reserves rights or refers to material that will be provided later.

Do not merge comments during drafting or legal review. If two comments are later judged duplicative, retain both in the Option 2 working copy until the user expressly approves deletion.

### Clarification contents

Every initial Tenderer clarification should contain:

1. `Proposed amendment:` the complete insertion, deletion or replacement associated with that comment.
2. `Reason:` the complete comment text.
3. `Current wording:` where necessary to understand a deletion or replacement.
4. `Related items:` other Part C item numbers addressing the same text or commercial theme.
5. `Source comment:` the Word comment number in the working copy only.

Do not use “refer to redline” as the substantive clarification. Reproduce the full proposed wording. Where one redline supports several comments, repeat the relevant proposed wording in each item so every item can be understood and answered independently.

Where a comment has no final proposed wording, state the precise reservation, information request or outstanding action reflected by that comment. Do not invent contractual language.

## Legal reference hierarchy

### Main agreement

Use:

`Clause [number] – [clause name] / paragraph [subparagraph]`

For a defined term:

`Clause 1.1 – Defined terms / “[Defined Term]” / paragraph [subparagraph if applicable]`

### Contract Particulars

Use:

`Contract Particulars / Item [number] – [item name] / sub-item or table row [label]`

### Annexures and schedules

Use:

`[Annexure or Schedule number] – [full name] / Item [number and name]`

If there is no formal item number, use the most precise available locator:

1. numbered section and name;
2. table number and name;
3. named table row or field;
4. `Whole annexure` or `Whole schedule` for heading-level comments.

Never identify an annexure or schedule item using only a page number.

## Reconciliation controls

### Comment control

The final Option 2 register must contain exactly 92 initial Tenderer item blocks and exactly one source comment number per block. Source comment numbers 1 through 92 must each appear once in the working reconciliation ledger.

### Shared-anchor control

Confirm that:

- Annexure I has three separate red blocks;

- Schedule 8 has two separate red blocks;
- none of these seven blocks was merged during formatting or review.

### Redline control

Map all material insertion/deletion clusters to at least one of the 92 items. Where multiple items rely on the same redline, list all associated item numbers. Classify unassigned changes as consequential, mechanical or formatting-only, with reviewer approval.

### Manual-style control

Inspect highlighted, coloured and struck text outside tracked revisions. Add any uncovered proposal to the nearest relevant comment item. If there is no related comment, flag it as an uncommented redline requiring a decision; do not silently create a 93rd item under Option 2.

### Annexure control

Review pages 147 onward separately. Verify the annexure/schedule name, item or table, and row label against the visible Word document. Heading-level comments must not inherit an item number from the preceding schedule.

### Formatting control

Check that all 92 issue blocks retain merged Item No. and Section / Clause cells, all conversation rows remain together where practical, table headers repeat on new pages, red blocks are visually complete, and long clarification text remains legible.
