# Planning Workspace Lifecycle

Use Planning Workspace to turn a business question or linked recommendation into a saved plan that a person can review.

## Main operations

- Create a strategy, initiative, or recommendation thread.
- Ask questions and check the cited business information.
- Draft a structured plan and resolve validation issues.
- Submit the exact plan version for a human decision.
- Create a new version when revision is requested.

## At a glance

| Input | Human decision | Output | External change |
| --- | --- | --- | --- |
| Thread title, conversation, cited business facts, and any linked recommendation | Whether the plan is complete enough to submit | A saved plan version and review status | None |

## Before you begin

- Confirm you are working in the intended business.
- Refresh time-sensitive source information before relying on it.
- Open the linked recommendation when one exists and read its evidence.
- Decide whether the thread is a broad strategy, a specific initiative, or work for one recommendation.

> **Important:** Conversation text cannot approve a recommendation or make an external change. Only the dedicated review and implementation stages record those events.

## Step-by-step

1. Open **Planning Workspace**.
2. Select an existing thread, or create a new thread with a clear title and type.
3. Describe the decision, dates, limits, and unanswered questions in the conversation.
4. Open citations and confirm the information supports the statement beside it.
5. Draft the structured plan.
6. Read any validation result and correct missing or conflicting details.
7. Check the plan version, objectives, actions, measures, and limits.
8. Select **Submit for review** when the exact version is ready.
9. Open Recommendation Inbox for the human accept, reject, or revision decision.

## Lifecycle and decisions

| Stage | What you do | What it means | External change |
| --- | --- | --- | --- |
| Conversation | Explore the problem and evidence | Working notes only | None |
| Draft plan | Create a structured version | A version is ready for checks | None |
| Submitted | Lock the exact version for review | A reviewer can decide on it | None |
| Accepted | Record that the plan is suitable | Later work may continue | None |
| Revision requested | Create a corrected version | The earlier version remains part of the history | None |
| Rejected | Stop that version | Recommendation status is unchanged | None |

## Troubleshooting

| Symptom | Likely cause | Safe action |
| --- | --- | --- |
| Submit for review is unavailable | No plan exists or validation has not passed | Draft the plan and resolve the shown issues |
| A cited fact looks wrong | Its source or date no longer matches the question | Check the source view and update the plan |
| The reviewer cannot see the latest wording | A newer draft was not submitted | Confirm the revision number and submit the intended version |
| Drafting fails twice | Required information or a service is unavailable | Keep the thread, stop retrying, and return after checking the message or connection |

## Worked examples

### Plan an end-of-season jacket campaign

Create an initiative called "August jacket sell-through". Ask for current jacket sales, stock, incoming purchase orders, and accepted past lessons. Draft a plan that names the date range, selected products, discount limits, and success measure. Submit revision 2 only after those details pass validation.

### Respond to a revision request

The reviewer asks for a lower discount limit. Return to the thread, explain the change, draft a new version, check the revision number, and submit it. Do not edit or describe the accepted version as though it changed.
