# Recommendations, Creative Review, and Audits

Use Recommendation Inbox and review screens to make a clear human decision without mistaking approval for completed work.

## Main operations

- Read the evidence period, source, assumptions, risks, and proposed action.
- Request approval, approve, reject, or continue planning as appropriate.
- Review the exact creative or deliverable version submitted.
- Use campaign audits as prompts for investigation.
- Record implementation and later outcomes separately.

## At a glance

| Input | Human decision | Output | External change |
| --- | --- | --- | --- |
| Evidence, recommendation, linked plan, creative version, or audit finding | Approve, reject, request revision, investigate, or take no action | A recorded review state and next step | Not by review alone |

## Before you begin

- Confirm the evidence dates and connected account.
- Open the linked plan when the recommendation has one.
- Check that the item on screen is the exact version you intend to decide on.
- Make sure the proposed action names what a person must check before any external change.

> **Important:** Strong evidence can support a decision, but a recommendation is still a suggestion. Approval records permission to continue; it does not prove that a campaign, budget, message, or listing changed.

## Step-by-step

1. Open **Recommendation Inbox** and select the item.
2. Read the evidence, dates, assumptions, risks, and proposed action.
3. Open or create the linked Planning Workspace thread when more planning is needed.
4. Review the plan decision and any submitted deliverables.
5. Choose the available action: request approval, approve, reject, accept, or request revision.
6. If work happens manually, record what actually changed and when.
7. If a supported execution action is offered, review its preview and confirmation before using it.
8. Confirm the execution result rather than assuming a click succeeded.
9. Return later to record or review the measured outcome.

## Recommendation states

| State | Meaning | Safe next action |
| --- | --- | --- |
| Shadow | Visible for review but not submitted | Check evidence or dismiss it |
| Pending approval | Waiting for a human decision | Approve or reject after review |
| Approved | Approved to continue | Implement through the shown method |
| Executing | A supported action is in progress | Wait and refresh status once |
| Executed | The supported action reported success | Verify the external result and monitor it |
| Execution failed | The action did not complete successfully | Read the error and verify external state before retrying |
| Rejected | The recommendation will not continue | Record a reason where useful |

## Review creative work

Check the brief, audience, product, claims, channel, and exact submitted version. Accepting a deliverable makes that version available for manual use; it does not publish or send it.

| Review choice | Output | External change |
| --- | --- | --- |
| Accept | Exact version is accepted for later use | None |
| Request revision | Feedback is recorded and a new version can be prepared | None |
| Reject | Exact version is not approved | None |

## Use campaign audits

Campaign Audit highlights supported structure and performance concerns. Open the named campaign or account, check current settings and complete-day results, then decide whether the finding needs a plan or no action.

| Input | Human decision | Output | External change |
| --- | --- | --- | --- |
| Current supported campaign information | Whether the finding is valid in the live account | An investigation note or planning task | None |

## Troubleshooting

| Symptom | Likely cause | Safe action |
| --- | --- | --- |
| Evidence is missing or old | The source is not ready | Refresh once, then check the connection if it fails |
| The wrong creative appears accepted | You are looking at a different version | Compare the version and review date before using it |
| Approved shows but nothing changed | Implementation is a later stage | Find the implementation or execution status |
| Execution failed | External state or confirmation no longer matches | Inspect the live account and error before any retry |

## Worked examples

### Review a budget recommendation

The recommendation suggests moving budget after a weak week. Check complete-day delivery, conversion tracking, current budgets, and the evidence period. Approve only when the proposal fits the business. After a manual change, record the campaign names, date, and actual amounts.

### Request a creative revision

A submitted email draft uses an unapproved shipping claim. Select **Request revision**, name the exact claim to remove, and review the new version separately. The original remains rejected for use.
